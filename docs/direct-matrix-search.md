# Initial direct-train inventory search

This document describes the retained CLI/orchestrator MATRIX policy. Normal V2 API discovery makes zero provider calls; selected-route API availability uses bounded strategic exploration rather than the full matrix. The CLI/orchestrator defaults to MATRIX for every mode. STANDARD's legacy 30-check ceiling no longer limits this search. Direct timetable services are preserved before schedule-only dominance, detour filtering and the indirect result cap.

The shared AvailabilitySession permits at most 32,768 budgeted checks per search. Each direct candidate may use at most 8,192, including exact whole-leg checks. An explicit smaller budgetLimit or maxRecoveryRequestsPerCandidate remains binding. PROGRESSIVE is an explicit compatibility option for the earlier low-budget allocation policy.

For n eligible ordered route nodes including both endpoints, and c requested canonical classes, the complete matrix costs at most c*n*(n-1)/2 distinct checks. ALL has eight canonical classes; explicit class lists and authoritative supported-class metadata narrow c. Exact session-cache hits cost no extra checks. Worst-case logical budgeted checks are 32,768 for the entire direct-plus-indirect search. Independently, the application safety ceiling admits at most 500 outbound availability requests globally per V2 search (configurable down to 1); independent provider rolling-window and monthly quotas still apply; shared-cache hits and inflight followers consume zero provider allowance. SDK attempts and additional fetch attempts are admitted at the owner boundary. Provider exhaustion stops new exploration and retains partial evidence; the logical ceiling is not a provider-call allowance. Each direct contributes at most min(8,192, c*n*(n-1)/2), subject to the shared remaining budget. The full eight-class matrix fits the per-direct bound through 45 route nodes (7,920 checks).

A whole-leg AVAILABLE result already provides maximum AVAILABLE coverage with no class changes and needs no interval recovery. Otherwise matrix recovery checks all classes on all forward pairs, including classes after an earlier usable result. Endpoint intervals come first in route order, followed by internal intervals by increasing span. WAITLIST, NOT_AVAILABLE and exact-request unsupported responses never imply interval-wide or train-wide exclusion. The existing path algorithm retains AVAILABLE/RAC edges and permits mixed-class paths. Unchecked or failed inventory remains unknown; exhausting a safety bound retains all discovered reserved portions.

All direct candidates are evaluated before indirect availability, regardless of the five-card display target. Indirect work retains its bounded allocator and may use the remaining shared budget. Provider concurrency, shared cache, inflight deduplication, cancellation, deadlines, burst limits and monthly quota are unchanged. They can stop execution earlier than these search ceilings; the ceilings are not a promise that a cold matrix will finish within the configured deadline or provider quota.

Results rank by reserved coverage, AVAILABLE-versus-RAC quality, train changes, class changes, connection safety, duration, distance and complete fare. Presentation groups equivalent route variants, selects each best variant, and marks the first five with actual AVAILABLE/RAC evidence initiallyVisible. Partial evidence remains eligible even with INVENTORY_CHECK_INCOMPLETE status; no status or availability claim is upgraded. Remaining journeys/variants stay in results for Show More.
